# Code of Conduct

## The Standard

Contributions are judged on technical merit. Full stop.

The quality of your code, the correctness of your cryptography, the rigor of your security analysis — that's what matters here. Who you are, where you're from, what you look like — irrelevant.

---

## What's Expected

**Do:**
- Know what you're submitting before you submit it
- Back up claims with evidence — benchmarks, CVEs, RFCs, proof-of-concept code
- Accept technical criticism without taking it personally — it's about the code, not you
- Give technical criticism directly — say what's wrong and why, not what might possibly perhaps be perceived as potentially suboptimal in some contexts
- Credit prior work when you build on it

**Don't:**
- Submit work you don't understand
- Waste reviewers' time with half-baked PRs
- Harass other contributors
- Introduce backdoors, intentional weaknesses, or supply-chain attacks — this results in immediate permanent ban and potential legal exposure
- Dox anyone

---

## Enforcement

Issues that violate the above get one response: a close.  
Repeat offenders get banned.  
Actual criminal conduct (supply-chain attacks, harassment, doxing) gets reported.

---

## The Point

This is a security tool used by real people to protect real data. The code has to be right. Everything else is secondary.

If you can write correct, auditable crypto code and find real bugs — you're welcome here regardless of anything else about you.  
If you can't — work on your skills, come back when you can.
